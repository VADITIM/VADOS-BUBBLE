# States

The Dynamic Bubble is a state-driven system: everything on screen is some bubble in some state, and every state is reachable from every other one by a named transition. This file is the vocabulary — which bubbles exist, which states each of them can be in, and which of those are built today. [bubbles.md](bubbles.md) says what all bubbles share; [motion.md](motion.md) says how the transitions between these states are allowed to move.

Rows are tagged **built** (on the phone now) or **planned** (specified, not written). A planned row is binding the moment it is built: it is here so nothing gets built the wrong shape first.

## Bubble kinds

| Kind | Where it stands | Built | States it can enter |
|---|---|---|---|
| **Main** | At the punch hole. The bubble. | built | Idle, Mod, Alert, Extended, Haptic, Pull, Push |
| **Satellite** | Beside the Main bubble, one a side, two at most. | built | Mod (by side), Extended, Haptic, Push |
| **Status** | Right end of the status bar, over the system's own icons. | built | Idle, Modus, Extended, Haptic, Pull |
| **Double** | Bottom of the screen, centred, alongside whatever Main is doing at the cutout. | built | none of the common states — see below |
| **Hidden** | Past the second satellite: a coloured dot, not a bubble face. | built | none; it is a count |
| **Lock** | Where the lock icon is on the lock screen. | built | none; it is an indicator that merges on unlock |
| **Notification** | Over the lock screen's own notification list, replacing it. | built | none of its own; a tap opens the app that posted it |
| **Now** | At the bottom of the lock screen, where a thumb reaches. Replaces One UI's Now Bar, and the lock screen is the only place it stands. | built, partly | Mod, Extended, Haptic; Pull and Push planned |

While a Now mod is standing in the clock the row is allowed **one** satellite, not two: the bar left over is not wide enough for a second, and a row that overflows into the punch hole is worse than a row that counts. A satellite losing its place is not hidden — it is run into the bubble, which takes the knock, and it comes back as the first dot.

Only the Main bubble takes mods, and only the Main bubble alerts. Everything else on this list either carries one thing for as long as it is true, or stands for something the system already draws.

## Structural states

What a bubble *is*, independent of which mod or content it is showing.

| Name | Was called | What it is |
|---|---|---|
| **Idle** | Closed | No mod true. Bare bubble, idle face, `compact` width. |
| **Mod** | Closed, mod-owned | A mod (media/clock/call) owns the bubble's shape: glyph, short reading, `playing`/`timing`/`calling` width. On the main bubble this is **Main-Mod**. A mod widens the bubble slightly, puts its own glyph against the left inset and its reading or secondary icons on the right. |
| **Satellite-left / Satellite-right** | Satellite | A second or third live mod, not the owner, drawn as a circle beside the bubble instead of inside it. A satellite only exists because a mod is behind it, so it is always a Mod state by side rather than by centre. |
| **Alert** | Alert | A fresh notification arriving: `alerting` (text) or `image` (with a photo), dwells and auto-closes. Main bubble only — an alert is by definition a thing that arrived, and only the bubble at the punch hole stands for arrivals. **One conversation is one alert**, and it stacks — see below. |
| **Alarm** | — | **Removed.** A ringing alarm is recognised and then deliberately ignored — no bubble, no alert, nothing. See [The alarm](#the-alarm). |
| **Extended** | Active / Grow / Open | Tapped open — the bigger module of the mod, with its options — full detail, own layout, no satellites: `expanded`, `picture`, `player`, `timer`, `history`. What it opens is a Tab (below). |
| **Haptic** | — | Held down, growing under the finger. In code this is the hold in progress, before it resolves to leaving for the mod's own app. **A bare bubble has no Haptic at all**: the hold is the way out to the app behind whatever the bubble is wearing, and an idle one is wearing nothing — there is no app and no panel to fall back on, since the quick settings belong to the Status bubble. It used to be armed anyway and then quietly do nothing when the timer came up, which spent the swell, the window growth and a third of a second of the touch on a gesture that was never going to happen. Not armed, an idle bubble answers a press with the band and nothing else. |
| **Pull** | — | Swiped down. Opens the notification Tab from any bubble at all — the one gesture no mod has claimed, so it can mean the same thing everywhere. |
| **Push** | — | Swiped up. Dismisses: an alert back to Idle, a satellite out of existence, a mod off the bubble, an extended bubble back to its closed self. Only meaningful when there is something to close. Every bubble that can be extended answers it — the main bubble and the Status panel — except the two on the lock screen, whose upward flick already means something else. It fires **once per touch**, latched: a touchmove is a stream, and unlatched every frame the finger stayed above the line fired the dismiss again, which is what "it triggers it multiple times until it breaks" was. |
| **Double** | Charging | **Built.** A true second main bubble — not owned by the first, not a Mod and not a Satellite. It runs alongside whatever the main bubble is doing rather than taking its slot, which is what makes it Double. It holds the system's own short-lived announcements that have no home on the bar — a recording that ended. **Nothing about the battery is one of them any more**: plugged in, running low and nearly out are all announced by the Status bubble, which is the one already carrying the charge, and a bubble opening at the bottom of the screen to say something about a number standing at the top of it was two places for one fact. Which leaves it with nothing live to say until the recording announcement is built. It has no common states because it is never interacted with — it appears, it says one thing for a few seconds, it goes, and it overlaps everything because in that moment what it carries outranks everything, which is why it stands above every other bubble in the stack. It costs no window, because nothing about it is interactive. **It stands at the bottom of the screen now**, centred, where the thumb already is. It used to stand beside the punch hole and ride the main bubble's own right edge every frame it was out — measured rather than placed, because the bubble beside it is a different width under every mod and three times that wide with an alert open, so a Double parked at the closed row's edge is a Double drawn *inside* an alert the moment one arrives. That whole per-frame magnet existed to keep two shapes out of one corner, and it was never a corner this bubble needed: what it announces has nothing to do with what the row is carrying, and the row is the busiest place on the screen to say it. Down there it rises out of the bottom edge and sinks back through it rather than merging home into the main bubble — a merge into a shape most of the screen away is a journey, not a merge. What it does still owe is the liquid: it merges with whatever it lands on, which on the lock screen is the Now bubble, and it grows the filter's region to the whole screen while it is out (`html.double-live`) or its skin is dropped outside the row's band and it goes back to painting its own opaque edge. |

Code's `state` variable carries `idle | alert | extended | haptic`. Pull and Push are named states in the model but resolve inside the gesture handlers rather than living in that variable — Pull ends in Extended on the notification Tab, Push ends in Idle or in a bubble that no longer exists. Do not add them to `state` unless something genuinely has to branch on being mid-gesture.

The old `state === 'active'` for a notification showing was renamed to `'alert'` first, freeing the string for what had been `'open'` — the two would otherwise have collided on one string for two different things. That string is `'extended'` now: what it names is the bigger module of a mod, and "active" reads as a bubble merely doing something, which every mod state is.

**How long an alert stands is a setting** (`alertDwellTenths`, tenths of a second because the store holds ints). How long is long enough is a reading speed, which is the one number here nobody else can guess.

**A channel message is titled after the place, and the head says the person.** Discord titles a server message `#channel (Server)` and puts whoever wrote it only in the message's own sender field, so the head row would name a room and never a person. It reads `Sender · Server` instead — the channel is worth nothing at a glance, the server is worth one word. A notification with no sender of its own is already titled after whoever sent it and is left alone.

**An alert is a conversation, not a message.** A second thing said by the same person while the alert is up appends beneath the first: the bubble does not close, does not announce itself again, and does not play its arrival a second time. Anything else makes a message impossible to read, because the act of reading it is exactly when the next one lands.

What it stacks is not accumulated in the page. A messenger posts one notification per conversation and rewrites it as each message arrives, so the whole run is already in the payload as `lines` — `text` is only the last of it. That run is there to say what has been *added*, and nothing else: **a fresh alert is one message**, whatever the conversation behind it is holding. Drawn in full it would put a backlog on screen and stack an alert nobody watched arrive. What is new is whatever comes after the count already taken — a count, never a search through the run, because someone sending "ok" twice has said two things and looking the last one up finds the wrong one. An app that posts a fresh notification per message has no `lines` and a new key every time: there the same person is recognised by sender and package, and a new message by the run saying something other than what is at the bottom of the stack.

**A notification being taken away is not the same as a conversation ending, and the difference is a few hundred milliseconds.** An app that posts a fresh notification per message cancels the old one and posts the new one in the same breath — and the removal arrives at once while the announcement is held back by `KILL_GRACE`, so the alert on screen was closed before its own replacement was allowed to speak. Every second message from a real messenger therefore played the whole arrival again over a bubble that had just shut, which is exactly what stacking exists to prevent, and it never showed in testing because an injected payload has no removal behind it. So `onNotificationGone` waits `GONE_GRACE` — longer than `KILL_GRACE`, or it is no grace at all — and `show()` cancels that wait: an alert that is being replaced is still standing, still holding the old notification, and so is still recognised as the same conversation.

The alert does not grow for it, and **one message is drawn exactly as it always was** — the box is as tall as the message and stands under the head row, with no free space to be anchored in and nothing to fade. Only with a second message does the stack take what the head row leaves and anchor to its *bottom* edge, so the newest line stands still where the eye already is and the oldest runs off the top under a fade, which is the end that has already been read.

The condition is the count of messages, not a measurement of whether they fit, and that distinction cost a build. Whether a stack has outgrown its room can only be measured against a box that has finished growing, and on the frame an alert arrives the bubble is still the closed one — 34px, which one line of anything overflows. Measured there it answered yes for a single message and stood it against the bottom edge of the alert under a fade, with a hole beneath the header. `:has(.message + .message)` cannot be wrong about how many children there are, on that frame or any other. Prefer a condition the first frame already knows over one that has to wait for a transition to be true.

An arriving line grows its own height from nothing, and that *is* the push: everything above it moves up because it is getting taller. Animated separately they read as a fade standing next to a jump. A photo is not a line in a conversation — the image alert is a different face at a different height with nowhere for a stack to grow — so a picture always arrives as its own alert.

**Merge** is not a state of its own — it is the transition a mod's arrival or departure runs *between* two structural states (Idle↔Mod, Mod↔Mod). The glyph is the cause and travels first; width is the consequence and follows once it lands. `mergeHold` holds the bubble genuinely Idle for the length of that flight so a mod's face never shows before the mod has actually arrived — see [motion.md](motion.md) for the glyph-as-cause rule this transition is built on.

## Mods

A mod is something that is simply true for as long as it is true, and it belongs to the Main bubble alone. Mods are a set and they stack: whichever arrived first owns the bubble's width, the next two become satellites a side, and anything past that is counted as a dot. First come, first served — the order is rotated by a sideways swipe, not by a ranking.

| Name | Code names | What it is | Built |
|---|---|---|---|
| **Media** | `playing` / `player` | A song playing. | built |
| **Clock** | `timing` / `timer` | The clock app's running timer. | built |
| **Call** | `calling` | A connected call. No Extended view of its own — tapping opens the call in its app. | built |
| **Battery** | Status' own announcement | Charging, running low, nearly out. **Not a mod**: it is the Status bubble's announcement, because that is the bubble already carrying the charge — and it is not the row's, because a charge level taking the bubble away from a song for four seconds is the one thing this arrangement exists to prevent. | built |
| **Torch** | Clock's own | The flashlight. Lives in the clock bubble, not in the Main row, and has no closed face: while the light burns the bubble stands open at its panel. | built |
| **Recording** | Clock's own | Screen or voice recording. Clock bubble, whole pill red, white content: it is the one state on this bar that has to be readable from the corner of the eye, and a coloured icon is not. Tap pauses and resumes, hold opens its panel — elapsed, and the button that ends it. | built |
| **Download / Upload** | Status' own slot | A file in flight, on the **Status** bubble now — one slot beside USB, an arrow pointing the way the file is moving, and a tick for a moment when it lands before it goes. It was the Clock's, with a moving glyph, a reading and a timeline along the bottom edge, and it moved because the line between the two bubbles is who started the thing: a torch and a recording are the person's, a transfer is the phone working for whatever it is attached to. Nothing of the old face is kept — the shape a slot can take is not the shape a whole bubble could. Its lifecycle lives in `status.js` (`setTransfer`), and `now.js` hands the transfer half of the host's one shade payload straight over rather than the host learning that one reading now feeds two bubbles. | built |
| **Discord video** | — | A stream or camera live in a call. | planned |

The first column is the name to use in prose and in new code; the second is what the existing code still calls it. Each mod pairs a resting shape with its own separate open shape, and there is no single string that could stand for both without collapsing two real states into one.

The glyph and reading a mod puts inside the Idle-Mod bubble are not subject to the boundary fade, which is a text behaviour — they only fade when they are animating outside the bubble's own bounds.

## Tabs

A Tab is the content of an Extended state: its own container with its own layout, reusable by anything that wants to show that content. Tabs are not mods. A mod decides which Tab its Tap and its Haptic open; a Tab does not know which mod sent it, which is what lets two mods show the same Tab with different values in it.

| Tab | Opened by | Built |
|---|---|---|
| **Notifications** | Pull, from any bubble. Tap on a bare Main bubble. | built |
| **Quick Settings** | Haptic on the Status bubble — it is that bubble's panel now, not the main bubble's. | built |
| **Media** | Tap on the Media mod. | built |
| **Timer** | Tap on the Clock mod. | built |
| **Flashlight** | Nothing — the torch is only ever seen open. The panel comes out with the light and goes home with it, at the media player's own width (`SIZES.player`). | built |
| **Picture** | Tap on an alert carrying a photo. Sized to the image rather than to a fixed box. | built |
| **Discord video** | Tap on the Discord video mod. 16:9 to screen width, or the video's own ratio if it is vertical. | planned |
| **Recording** | Haptic on the Now recording bubble: elapsed and stop. It shares the flashlight panel's box rather than opening a second one — it is the same bubble held down. | built |

### The alarm

**Nothing happens.** A ringing alarm is recognised — `AlarmWatch.isAlarm`, off the notification the way the timer is read, told apart from everything else the clock app posts by its **full-screen intent**, with calls excluded by name because they have a bubble already — and recognised for one reason only: so that no bubble, no alert and no state comes of it.

It used to be the one state allowed to take the whole screen, with the clock app's own buttons on it. What that bought was a second thing to dismiss at six in the morning: the phone is already ringing and the clock app already owns the screen while it does, so anything of ours over the top of it is in the way of the only interaction that matters. The test stays because without it the alarm's own ongoing notification would be read as a state worth carrying, which is the bug the whole branch exists to prevent.

## What the Clock bubble carries: the Now mods

**Built.** Torch and Recording, shown in the bubble at the left end of the bar — the clock's. Download and Upload were here and are the Status bubble's slot now; see their row above. There is no Now bubble up there any more: it stood on One UI's flashlight chip a few pixels right of the clock, so the clock had to leave whenever a mod came out and the row had to stand aside for the pair of them, which is a great deal of motion spent on two shapes avoiding each other. One bubble carries both, and the name Now belongs to the lock screen's bubble alone.

They are one set with one owner at a time, chosen first-come-first-served, and `setNowMod` is the only place a Now mod's life is written down: the time stands aside when the first one starts and comes back when the last one ends, whichever mods those happen to be. Torch is one of them rather than the special case it used to be, with one difference: it has no resting face. A torch that is on arrives open (`keepTorchOpen`) and cannot be tapped shut, because there is nothing behind the panel to shut it back to — the light going out is what takes it away.

**The arrival is two beats and the order is the rule.** The time gives way first — the digits fade and walk left, which is a reading leaving rather than a reading being covered up — and the box grows to the mod afterwards. That is [motion.md](motion.md)'s glyph-as-cause with a whole reading in the cause's place. Going back is the same thing backwards: the width first, the time after it.

Each mod asks for its own width (`NOW_WIDTHS`) and the bubble is that wide, because it grows rightwards into bar the row has just given up and has nothing to negotiate with. The resting width is the digits' own — `auto` — so the script writes the measured pixel width into `--clock-width` before it grows: a transition out of `auto` is not a transition, the browser jumps straight to the end. The torch is outside all of it, since it is never closed.

Neither a recording nor a transfer is watched by a source of its own. Both are ongoing notifications, which is what the platform means by "this is still going on" — the same reading that puts a running timer in the row. A transfer with an *indeterminate* bar is left in the shade: an app saying it has no idea how far along it is has nothing a timeline can honestly draw. A finished one is not dropped on the spot either, because apps take a progress notification away the instant it completes and the only thing the person would ever see is the bubble vanishing; it stands there wearing a tick first.

Paused is read off the recorder's buttons, not off a field — no recorder posts a state, but a running one offers "pause" and a paused one offers "resume". Both words are matched in both languages the phone speaks, because neither word is ours.

Whether the row stands aside for a mod standing in the clock is a setting (`nowPushesRow`, on by default). Off, the row keeps its place and its two satellites, and the clock takes only the bar that is actually free.

### Push on a Now mod

A swipe up takes the mod off the bubble and gives the bubble back to the time. It is a Push in the sense this file means — the mod comes off the bubble, not out of existence — so the recording goes on recording and the file goes on arriving; the mod stays dismissed until it actually ends, or a transfer's next tick would bring the bubble back a fraction of a second later. If something else is happening it takes the bubble over on the spot rather than the shape flying home and coming straight back out.

There is no flight to write down any more. The bubble the mod was standing in is the clock and the clock is not going anywhere: what leaves is the mod, and what arrives in its place is the time, on the same two beats every other hand-over here has.

## Status

**Built.** The Now bubble's opposite number, at the right end of the bar, standing on the system's own icons the way the clock bubble stands on One UI's own clock and the chip beside it. It replaces battery, wifi / mobile connection and the signal bars, and it carries Modus as well.

**Do not disturb is not one Modus but as many as the phone has modes.** One UI's Modes are one automatic zen rule each, and which of them is running is what the person set — sleeping, a mode for one person, work — so the bubble wears an icon for the mode rather than one crossed circle for all of them. Samsung's own icon for a mode is not readable: `iconResName` is null on every Lifestyle rule this phone has, so there is nothing to load and draw. What is readable is the **name**, which the person wrote, and the page matches it against a small glyph set — sleep, heart, work, driving, exercise, gaming — falling back to the plain ring for a mode nobody here knows. The name comes over the shell rather than from `NotificationManager`: `getAutomaticZenRules` needs notification policy access, which this phone will not hand over (`cmd notification allow_dnd` runs without complaint and grants nothing), and the same rules are in a dumpsys the Shizuku shell already reads. It is greped on the phone, so one line comes back however long the dump is, and it is asked for again only while the answer is still missing — Shizuku binds a moment after the service starts, and the read that matters is the one at boot, for a mode that was already running before the bubble existed.

A Modus is not a mod in the sense the main bubble means: it colours the whole bubble rather than taking a slot in it. While one is active the Status bubble wears that Modus' colour and puts its icon on the left. Hotspot, USB and Bluetooth are the three, in that order — the order is how much of the phone is currently being lent to something else, which is what the person holding it cares about — and exactly one is worn at a time.

The colour arrives through the **border** rather than the background, because the skin reads its edge colour off the box it mirrors: written there it is in the liquid without a second rule keeping the two in step, the same way an alert's accent is on the main bubble.

It answers three gestures, in the order they mean things everywhere else on the bar, and it used to answer one. A tap is **Extended** and opens the quick settings panel — which is this bubble's own now, not the main bubble's; see below. A **pull downwards** is the same ask made with the hand, and it is the one gesture this bubble owed more than any other: it stands on the shade's own icons, and a bubble standing there that does not answer a downward pull is a hole in the gesture underneath it. A **hold** is the way out to the app behind it, which here is the system's own settings screen for whatever it is currently reporting; a panel of ours that both toggled the radios and named the networks would be a second settings app rather than a status bubble. Under all three is the ordinary rubber band, so the bubble is an object being pushed about rather than a control waiting for a threshold — and the threshold is felt at the crossing, not on the lift.

A fourth way in is not a gesture on this bubble at all. One UI's diagonal swipe from the right edge belongs to SystemUI's quick settings and cannot be pointed at ours, so the panel is given an app to be — `StatusPanelActivity`, a launcher entry that toggles it and finishes — and whatever the phone can bind to "open an app" opens it. It **toggles**, because a gesture is one thing the hand does and the same gesture has to put the panel away. See [architecture.md](architecture.md#the-control-panel).

### Clock-Status-Idle and Main-Status-Idle

**Built.** What the tap that opens the quick settings panel does to the other two bubbles still standing on the bar, while the panel itself is `#quick-panel.showing` — a structural state each of Clock and Main enter and leave together with it, named after what triggers them rather than given a place in `state`'s own string. Clock and Main carry it as an explicit `.corner-grow` class, toggled by `openStatusPanel()` / `closeStatusPanel()` in the same call that adds or removes `#status`'s own `.open` — not read off `:has(#quick-panel.showing)`. It was read off `:has()` once, and that indirection was the actual cause of two of this state's motion bugs: the class carrying the corner-grow properties and the class carrying their `transition` list matched at different points in a `:has()`-driven cross-tree recalculation, so a size change and the translate beside it did not reliably start on the same frame, and one read as instant while the other eased. Toggling one class, in the one function that already owns every other side effect of opening the panel, makes the before/after style snapshot unambiguous.

The Clock reaches for the top-left corner exactly as it always has — grown, never moved, past the top and left edges by `--edge-over` — and now additionally opens its own width to the right and puts the date in the room that opens up (`#clock-date`, revealed by the same `.corner-grow` class, painted every tick in `clock.js` alongside the time so it is never stale when the corner happens to go idle at midnight). The date used to be shown with `display: none` → `display: inline-flex`, which is a discrete property: it cannot transition at all, so the *reverse* — panel closing, `.corner-grow` coming off — snapped the date away in the same frame rather than fading it, however carefully the *arrival* keyframe had been tuned. It is `display: inline-flex` at all times now, collapsed to `max-width: 0; opacity: 0` at rest and opened to its measured width on `.corner-grow`, so both directions are the same continuous properties easing on the same clock.

**Main no longer reaches the top-right corner at all.** It used to: a small rightward shift plus a `padding-right` grow, fusing with Status the way Clock still does. That is gone — Main leaves the corner entirely while the panel is open, and the only merges it owes are sideways and at the very bottom, with the screen's own edges, not with Status or Clock.

**Main docks at the bottom of the panel instead**, growing taller, and takes over what used to be a separate foot module (`#quick-media`, now deleted) inside the panel: the Media mod's real face (`#player-face`) is reused verbatim — one piece of markup for a song playing, not two — and a **Transfer strip** (`#dock-transfer`) stacks beneath it when a transfer is also in flight. **Transfer becomes Main-eligible for exactly this one state** — see [bubbles.md](bubbles.md#mods-are-eligible-by-bubble-not-by-availability) for the scoped exception this makes to the mod eligibility table; everywhere else on the bar, Transfer stays Status/USB's own slot, because "who started it" is still the line that separates the two bubbles' mods.

The dock is measured, never a hand-picked constant: `status.js`'s `fitPillDock()` reads `STATUS_PANEL`'s own geometry (the box `fitStatusPanel()` already computes) and the screen's height, and writes `--pill-dock-width` / `--pill-dock-top` / `--pill-dock-height` before `.panel-dock` is added to the bubble — so the box is ready the instant the class starts easing `width`/`height`/`top` on the ordinary `--pill-transition`, exactly the way every other size change on this bubble already works. `padding-bottom` joined that list for the same edge-over technique Clock and Status already use on their own corners: the box grows past the screen's actual bottom edge by `--edge-over`, so Main's own edge merges with the screen there instead of stopping short of it. Height depends on which mod is live — a base height for Media alone, taller when Transfer is also stacked beneath it, always at the very bottom of the box.

While docked, `showFace('player')` is called directly rather than through `setSize()` — the normal Extended sizing (`#pill.player { width:340px; height:190px }`) is for the tap-to-open case and would fight the dock's own box, so the dock bypasses it and lets `#pill.panel-dock`'s own CSS own the geometry while `#player-face`'s markup (already `.face { inset: 0 }`, already kept live at all times by `mods/media.js`'s `paintMedia()` whether or not it is showing) simply fills whatever box it is handed.

**The knobs and levels directly above the dock flex-scale with it.** `#quick-row-knobs` and `#quick-row-levels` used to hold fixed sizes; now their `flex-basis` gives way as `#quick-row-body`'s own share of the panel's height shrinks under a taller dock, the same way the old foot module already took room from "the states and the levels" for a playing song — except the controls themselves now resize rather than just yielding empty space around fixed ones. The connector grid up top (`#quick-row-links`, the battery) is untouched; the room comes only from the row directly beside the dock.

The old top-right corner-grow's own touch-proxy trick is retired with it: Main's proxy while docked is asked for by `fitPillDock()` itself (`bridge.setWindowBounds`, the same call `applyWindow()` uses elsewhere), and handed back to whatever the bubble's real state already was (`applyClosedWindow()`) the moment the panel closes — never a value the dock invented.

The Status bubble reaches for the same corner too, the same way Clock does and as *itself* — it does not become anything else to do it. `#status.open` used to shrink this bubble into the battery: the box's own shape stopped being a bubble and became a tall narrow cell, and that was the bug rather than a feature reused too far — a shape that changes what it *is* to open a panel reads as vanishing and being replaced, however smoothly the box eased, which is exactly what "the Status bubble disappears" was. The charge moved out to be a `.quick-bubble` of its own beside the six connectors (see [The panel](#the-panel) below), and what is left for the Status bubble is the same idle reach Clock makes and nothing more: grown past the top-right corner by `--edge-over`, mirrored off Clock's own technique since this box is `border-box` too — `right` and `top` reset to the same absolute overhang Clock's `left`/`top` reset to, and the padding on the side facing the corner grows by exactly the distance that reset moved the anchor, so the far edges land back where they already were. `top`/`right`/`padding` are ordinary entries in `--status-transition`, so this eases on the bubble family's own clock exactly as Clock does. Its one difference from Clock is that its *content* is centred both ways at rest rather than pinned to a corner, and that content is the small icon row drawn inside `.status-face` — a child positioned `inset: 0` inside the growing `#status` box, which is why `justify-content`/`align-items` on `#status` itself never reached it: those alignment properties only govern normal-flow flex children, and an absolutely-positioned child with every inset explicitly set is excluded from that, however the parent's alignment is written. Flipping `#status`'s own alignment was therefore dead weight rather than a fix, and the icon row went on recentring — visibly drifting downward — as `.status-face` filled more and more of the box on every frame of the grow. The alignment belongs on `.status-face` itself: `#status.open .status-face { align-items: flex-start; justify-content: flex-end; }` pins the row to the box's fixed corner — top and right are the edges that do not move as the box grows — from the first frame of the open, so there is nothing left to recentre into. The bubble also keeps its skin for the whole time it is open (`isSkinned('status')` in `liquid.js` no longer excludes `.open`) — dropping the skin was right while this box was becoming the battery's own flat cell, and wrong once it went back to being an ordinary bubble merging with its neighbours, which is the entire mechanism the corner-fuse below depends on. It stands in its grown corner for as long as the panel is open, not merely in passing. With the shape fixed and Main also grown into the same corner, the gap between them is small enough for the ordinary goo merge (`meltBy()`, [motion.md](motion.md#liquid)) to fuse the two on its own — nothing here schedules the merge, it is read off the measured gap like every other one on this bar.

**The panel's own box did not ease at all.** `#quick-panel` is a bare rectangle sized from four CSS variables (`--quick-left/top/width/height`), written once by `fitStatusPanel()` to their final values with no transition property on the element — so the panel snapped to its full open size the instant those variables changed, while its sixteen modules staggered in on top of a box that had already finished moving. It now carries `transition: left/top/width/height var(--grow-ms) var(--ease-grow)`, on the same clock the corner-grow reaches use, so the whole panel's own arrival is as visible as its contents' pop. `STATUS_PANEL.ms` in `status.js` — used for `stirLiquid` and settle-timeout bookkeeping, not a CSS duration — is 340 now to match `--grow-ms` rather than the 220 it had drifted to, which had nothing left in the CSS agreeing with it.

Open, it answers the **Push** every extended bubble owes: a flick upwards puts the panel away. That reading runs *alongside* the ordinary routing rather than instead of it — an open panel is full of switches whose touches have to reach the elements that know what to do with them, so `bridge.js` feeds `statusPanelPush` the same stream it feeds the switches, and a flick and a tap on a switch are told apart by how far the finger travelled. It used to live inside `statusTouch` behind an `if (statusOpen)`, which is a branch that could never run: `statusTouch` is only ever called while the panel is closed. A gesture guarded by the very state that stops it being delivered is dead code that reads as a feature.

### The panel

The quick settings were a face on the main bubble, opened by holding a bare one. They are the Status bubble's panel now, and `STATUS_PANEL` is the box they take — the whole screen less a margin, mirrored into the CSS so the number is written once.

**The panel is not a box with groups in it. It is a set of bubbles.** Six connectors, six states, three levels and USB are sixteen bubbles standing over a frosted screen, each painting its own background and each with its own arrival and departure — and no pane and no blob between them, because a grid of controls standing a hair apart is not a row (see [motion.md](motion.md)) — and there were six until the groups were broken up, because a group is still a box with a heading on it: Connections, Display and System were three shelves, so one switch could not be thrown in or slung home on its own, and each of those headings was a word explaining a glyph that had already said it. What survives of the grouping is the *order*, which is a grouping nobody has to read. It was one box holding four groups, and what that bought was a *card*: the box was the thing that arrived and the controls were its contents, so nothing in there could neck into anything, be thrown in on its own, or be slung home on its own. A module standing by itself is a bubble in every sense [bubbles.md](bubbles.md) means one. Media and Transfer are not modules in this set at all any more — see [Clock-Status-Idle and Main-Status-Idle](#clock-status-idle-and-main-status-idle) above: they are the Main bubble itself, docked at the panel's bottom rather than standing in its grid.

**The charge is a module now, standing beside the six connectors in `#quick-row-top` rather than beside the sliders.** It used to stay with the Status bubble and be the one reading that bubble's own box became — `#status.open` grew down into a tall narrow cell, and the charge was that cell's whole content — which meant the one bubble the panel needed to feel like the other fifteen never could: it changed shape to open rather than growing the way they do, and where the fifteen arrive staggered out of a fifth of their size the sixteenth simply *became*. The drawing survives every move exactly (`#quick-battery`'s terminal, well and fill are unchanged); only the box it stands in does. It stood beside brightness and volume for a while, at `flex: 1` in their row, and that read wrong for a different reason than the tall cell did: a level is a hand-set amount and the charge is a reading, so the eye kept comparing a reading against two things it is not. It stands beside the connector grid instead — a fixed 64px column at the grid's own height (`--quick-links-tall`), the same "what is true right now" family the six links are answering for. `#quick-battery` keeps its `.quick-bubble` class for the arrival stagger and the pop it shares with every other module, but not that class's card: `#quick-battery` overrides `.quick-bubble`'s background and border to none, since `#battery-cell` already draws the cell's own well and outline — a card behind a card was the battery wearing two backgrounds at once. The Status bubble itself is described above, under Clock-Status-Idle and Main-Status-Idle.

**Each module grows into its own place, out of a fifth of its size, and nothing about it travels.** The arrival is the bubble's own Extended-to-Idle collapse run backwards and not an animation of the panel's: `--grow-ms: 460ms` on `--ease-grow` with the face crossing over 280ms inside it is what every state a tap opens takes, and a module opening is that state change written for a smaller box. The overshoot at the end is `--ease-grow`'s own, so the module meets its size rather than inflating past it — a pop nobody had to write. It has been three other things. It came out of the Status bubble as a drop a twentieth of its size and crossed the screen, which is six journeys to watch before anything can be read. Then it was a short rise from below with a tilt corrected on landing. Then a measured throw from under the bottom edge of the screen with a two-phase shot and a magnet at the top of it — and that one was tuned three times and read as too fast every time, because a module crossing most of the display in the clock a bubble collapses across two hundred pixels in is several times faster than the thing it was being matched against. What retired the tilt with it is that nothing travels any more: fifteen shapes rising the same way read as one sheet being slid up, and fifteen shapes growing where they stand cannot read as a sheet at all.

**They arrive in a shuffled order, five milliseconds apart.** The rank is the only thing written per module now — there is no start position to measure and no tilt to correct — and it is reshuffled on every open because a fixed order is a sequence that gets learnt and a learnt sequence reads as a loading bar. A module's contents cross over the growth rather than racing it, on the same 280ms the pill's face takes inside the same 460: the contents scale with the box, so without it the glyph and its label stand legible at a fifth of their size for the first frames, which reads as the module being zoomed rather than grown. The other thing on a clock inside a module is the levels' pour, which is liquid running up a well that has to exist first.

**The charge is in that shuffle now, and takes the same rank-staggered arrival every module beside it does.** It was exempted for a while, on the argument that a set where fifteen things are thrown and one is placed reads as one thing being placed — but the one placed was also the one shape on the screen that changed what it *was* to arrive at all, which the bubble it belonged to could only do by not being a bubble for the length of the open. Once it is a `.quick-bubble` like the rest, exempting it from the shuffle is exempting it from being one of them, so it takes a `--pop-rank` and grows out of a fifth of its size the same 460ms the sixteen around it do. The one thing still on its own clock inside the cell is the pour — the liquid running up out of the well's own floor once there is a well — and it keeps the same `--pop-rank`-based delay `.level-fill` uses rather than a term of its own.

**Closing is the growth run forwards, which is the collapse it was taken from.** Each module shrinks back to the fifth of its size it grew out of, faster and on a tighter stagger, with no overshoot to watch — `--ease-leave` has none, and an anticipation before a leave is a thing bracing. It takes a fade with it where the arrival has none, and that is not a second move for one fact: the pill has an idle box to collapse *to* and a module has nowhere to land, so what is a shape change for the bubble is a shape change and a departure here.

**The modules carry no glass and they are not liquid either.** The frost under them is the screen's, not theirs — a pane per module frosts the same wallpaper the scrim has already frosted, so every module came out darker and duller than the gaps between them and the set read as six grey cards. They were still blobs after that, necking into each other and into the charge, and that half is gone too: **a grid is not a row.** The melt is one number for the whole goo layer, read off the smallest gap between any two shapes in it, and these fifteen stand a hair apart by design — so with them in the layer the melt sat pinned at its ceiling for as long as the panel was up, every module welded to its neighbours into one sheet with dents in it, and the row at the cutout welded along with them because it shares the layer. Necking is what two shapes do when they come near each other; it is not what a grid of controls does when it is simply laid out. So they paint their own background and border like any ordinary box, `html.liquid` leaves them alone, and their names came out of `BLUR_PANES` on both sides at once — with no blob there is no index left to reserve.

**Behind all of it the whole screen is frosted, on its own number.** `#quick-scrim` is a pane without being a blob — a full-screen shape in the goo layer would weld every bubble on the canvas into it — so it rides the blur bridge alone, prepended to the spec `sendBlurFrame` sends, which makes it pane 0 and every blob's pane its own index plus one. `SCRIM_BLUR` is a setting separate from `BLUR`, because how hard the screen behind a panel is frosted and how hard the glass under a bubble is are two different asks: One UI frosts its own quick settings far harder than it frosts a pop-up. It is the one pane here that fades by changing its **strength** rather than its size. Every bubble's glass shrinks on its own opacity, because a bubble's glass is the bubble and a shape closing to its middle is what a bubble leaving looks like; a screen has no middle to close to, and shrunk it read as a rectangle of blur collapsing towards the centre of the wallpaper. So it keeps the whole screen for as long as it is there at all and sends `--scrim-frost` as a sixth number in its region — the share of `SCRIM_BLUR` the host is to apply — which is the only way a compositor blur can move at all: it is a fixed number on a `View`, so a ramp is that number re-applied per frame. It comes up and goes home over **0.45s**, which still makes it the longest-lived thing on the screen and deliberately so: it is what the panel was standing on, so it outlives the panel rather than leaving with it. It was 0.6s up and 1.1s home, and 1.1s is two and a half panels now. The dark ground over it is separate and still goes in 140ms. Two consequences: the mirror has to be stirred for the whole 0.45s or the blur stops at whatever strength the last frame sent, and `--scrim-frost` has to be a registered `@property` or it is a string, and a string does not interpolate — unregistered, the whole ramp is one step on the transition's last frame. It is also the panel's own background, so the tap that closes the panel lands on it; it is a touch target only while the panel is up, or a full-screen element would swallow the phone.

**It is the screen, to all four edges.** `STATUS_PANEL` is measured rather than written down (`fitStatusPanel`) — the whole width less `STATUS_MARGIN` a side, and everything from the line the row rests on down to that same margin at the bottom, `STATUS_MARGIN_FOOT` being that number rather than one of its own. It was thirty, to keep the transfer bubble at the foot clear of the gesture handle; the handle is drawn over the panel rather than under it, so the twenty extra pixels bought nothing but a strip of frosted wallpaper along the bottom of every open — because a screen is not a constant and the panel is now the size of one. It was the media player's box, and what that bought was nine controls and a battery crammed into a card with the rest of the screen empty behind them; a level wants height more than anything else in this project and a thumb wants room. The top is read off the closed bubble's own box plus `--grown-pad` rather than re-derived from the three properties the host writes that line from, and it is measured **on the way open** and on a resize, never at load: at load this bubble has not been born and there is nothing to measure.

None of the rest of it changes, and that is the point of doing it this way. It is one bubble, drawn on the one canvas, growing out of the closed one and merging with whatever it passes; the filter region grows to it (`--liquid-tall`) exactly as it did at card size, and the proxy is asked for before the growth rather than during it. What is different is only how much of the screen those numbers are.

**The charge is a cell in the top right corner.** The panel is a column, the controls keep their own heights at the foot of it where the thumb is, and the charge stands in the corner above them at the size of a battery rather than at the size of a panel. It took every pixel the controls left for a while — `flex: 1` on a meter most of a phone tall — and what that bought was a reading that could be had from the doorway of the next room and a set of quick settings that read as a footnote under it. Height is not what a charge needs; a shape that says "battery" without being labelled is, and the cell is that shape.

Two reasons, and the first is enough. **Every switch in it is this bubble's subject** — a radio, a cable, a mode the phone has been put into — and none of them are the main bubble's, which carries what has *happened*. And a panel belongs to the bubble it grows out of: an interface where a hold at the cutout opens a box about the icons at the far right is two places for one thing.

All of its height is taken downwards, since the top edge is the line the row rests on and an open bubble that climbs is one that has left the bar. Everything in it is sized for a thumb rather than for a cursor: each cell is a box the whole of which is the target, the gap between them is a hair, and the switch is the one the torch's slider already uses rather than a shrunken copy of it. That is not a taste change — a tap that missed a control landed on the panel's own background, which closes it, so an imprecise finger read as the panel refusing to work.

**One bubble is extended at a time.** Whichever one is opening puts the others back to idle first — `becomeExtended()` for the main bubble, the same two lines at the top of the Now and Status panels' own open functions. Two open panels are two answers to one screen, and the one that was already standing there is the one nobody is looking at any more. The rule belongs to whoever is arriving rather than to a watcher counting them.

**A gesture that starts on a control belongs to that control — every control, not the two that were noticed.** The flick that puts the panel away may begin on the scrim and nowhere else. It used to begin anywhere that was not a `.level`, which was the one clash anyone had caught (a brightness drag upwards is a dismiss drawn in the same stroke), and the rule was right while the exception was a list of one. Every module here is grabbed, not only the two bars: a knob pressed and held wanders, a link is pushed at, the charge is held to reach Samsung's own battery screen, and all of them cross the twenty-four pixels the push reads as a flick sooner or later. From outside, that is not "the dismiss is greedy" — it is **nothing in the panel can be grabbed at all**, because whatever the finger did the panel went away under it. The scrim is the only thing under a finger that means "not a control", so it is the only thing the push may start on.

**The background does not close the panel.** A tap on an open *bubble* closes it, because the bubble is the thing that was opened; the scrim is not the panel, it is the room the panel stands in. The panel fills the screen to every edge now, so most of what a thumb lands on reaching for the bottom row is background — and a background that dismisses turns every missed press into a panel that vanished for no reason the finger can account for. The scrim keeps its `pointer-events` either way: it is what the flick has to start on.

**The levels are 140px wide, and the states beside them are what gives.** A level is dragged rather than tapped, and a thumb travelling up a 48px column is a thumb mostly off it. The two columns are one width in `#quick-row-levels`; the states to their left are `flex: 1` and hand the room over, so there is no second number to keep in step. It was 156 until the panel gained ten bubbles, and the room came from here because this is the one pair of shapes in the panel wider than a thumb needs.

**The connectors are a two-column grid with the charge beside it.** All six carry the name of what they are attached to — hotspot, aeroplane mode, location, mobile, wifi, bluetooth — and each takes one cell of a two-by-three. It was five columns of two-column cells for as long as the cable took the narrow fifth on its own; the width per connector is unchanged, because two of five and one of two are the same half. Nothing spans any more, so no cell is placed by hand: the auto flow lands all six exactly where a written-out `grid-area` would have, and six areas kept in step with six buttons is a second copy of the markup. The charge is not a cell in that grid: the Status bubble hangs there and is not in the frame's flow, so the room for it is subtracted with a padding rather than held by a placeholder that would have to agree with a bubble it cannot see. It is 96px wide now rather than 64 — at a third of that the cell was a stripe, and a level read off a stripe is a level being measured rather than seen.

**Three of the connectors have no settings key behind them, and each fails differently.** Aeroplane mode is `cmd connectivity airplane-mode`, not `settings put global airplane_mode_on`: the setting alone leaves every radio up under a phone that says it is in aeroplane mode, because the broadcast that would take them down needs a permission no sideloaded app gets. Location is `cmd location set-location-enabled`, read back off `location_mode`, which is a mode rather than a flag the way `zen_mode` is. The **hotspot is not read from the shell at all** — Samsung keeps no key for it — and it is not written as one either: starting a softap from the shell means handing it an SSID, a band and a password, which is this app inventing a network rather than switching the phone's own one on, so it clicks One UI's own tile the way the recorder does. Its state comes from the tether broadcast `ConnectivityWatch` already listens to, which is why it is painted in `paintModeLabels` rather than in `paintToggles`: that function runs on both clocks and `paintToggles` only ever runs on the shell's.

**Media and Transfer no longer take turns at the panel's foot — they stack.** That used to be a foot module of its own, base mod media with a transfer taking it over while one was running; it is Main's own dock now (see above), and a transfer no longer displaces the song — it stands beneath it, always at the very bottom, because a dock with both true has room to say both rather than picking one. Main is the bottom-most thing in the column, so it gives the panel's own bottom margin back and runs into the screen edge: an edge a bubble touches is an edge the panel is attached to.

**Nothing on the Status bubble clips, in any state.** `#status.open` used to hide the part of its face it had not opened out to yet, which was worth having while the box was a bubble with glass on it and the growth was the thing being watched. It is neither now: the skin comes off for the whole of `open`, so the box draws nothing and there is no growth to hide anything behind. What is inside it is the charge, which does not fly at all — the growth is its arrival — so there is nothing left for a clip to do but cut the overshoot off the box's own landing, which is the one thing no bubble here permits.

**The panel is its own size before the bubble is.** The face used to be laid out with `inset: 0`, which is the bubble's box — and the bubble's box is *animated* for 300ms on the way open, so the whole panel was re-solved on every one of those frames, four links, two levels, six knobs, the cell and its crests, while the liquid mirror was reading rectangles off the same document. That is the whole of "the panel is laggy": one layout was being paid for twenty-five times. It is sized from the same two numbers `#status.open` is given (less the bubble's own two pixels of border, since `inset: 0` measures against the padding box), so the layout is computed once and the growth is a clip over a picture that has stopped moving. `#status.open` is what clips, and it costs the skin nothing — the liquid is mirrored into a layer outside this element.

**A module is filled, not uncovered.** The box arriving is one movement and what is in it arriving is another, and the panel used to have only the first: every control was already at full size behind a 160ms fade. The face crosses over the growth on the pill's own 280ms, a level's liquid runs up out of its own foot once there is a well, and the cell swells while its own liquid pours in behind the glass. What the controls no longer have is an arrival each — the states were thrown in small and off true while they were circles inside a box, and since every one of them became a bubble that arrival is the box's, one owner. Every one of these runs `backwards` and never `both`: a fill mode that holds the last frame goes on writing `scale: 1` for the life of the panel, and an animation outranks the `:active` rule underneath it — `.quick-mode:active` and `.quick-knob:active` are both `scale`, so it would leave every press response in the panel dead.

**The panel stands clear of the row, not merely below it.** `--grown-pad` is measured from the line the closed row rests on and the row's bubbles are 34 tall, so a panel placed at the pad alone begins eight pixels *above* their own bottoms. That was first a liquid fault and is now only a spacing one: while the modules were in the goo layer the connectors on the top row grew necks up into the Clock and the Main bubble and the three drew as one body of liquid, and out of the layer they merely stand too close to a row they are not part of. `--quick-clearance` is the twenty-two pixels that buy the gap, and it is mirrored by `QUICK_CLEARANCE` in `status.js` because the stylesheet places the charge and the script places the frame beside it, and the two have to land on one line.

**It is one column of bubbles, read top to bottom**, in the order the readings matter: the connector grid across the top with the charge beside it, the six states below with the two levels against the right edge, and the media/transfer module at the foot. The frame they stand in (`#quick-panel`) is never seen and never touched — it exists so that where a module stands is a flexbox and two grids rather than sixteen sets of coordinates that have to be kept in agreement, and so the whole set can be told to arrive or to leave in one class.

**No modules where the design has five.** The design groups the round buttons under headings; there are no headings here at all any more, because a heading on a bubble is a label and this panel has none. The six states stand as six bubbles in the order the two headings used to say — the three the screen answers to, then the three the phone does. The design's header row, a Settings shortcut and a power button, is not built: neither is asked for, and neither has a host call behind it today.

**Nothing in it is a switch.** A link is up or it is down and a state is on or it is off; neither has a middle for a knob to travel across, so a track is a promise the control cannot keep. The six named connectors — hotspot, aeroplane mode, location, mobile, wifi, bluetooth — stand one cell of a two-by-three wide, with the name stacked under the glyph rather than beside it: side by side, every reading in the panel came out as "Vod", "sta", "not" — after the glyph and the padding a cell leaves about twenty pixels for a network's name, and stacked the whole cell width is the name's: what each of them carries is a *name*, and a name wants width rather than height. Mobile joined them because it is the same kind of fact as the radios beside it and the bubble on the bar already reports it; USB is the seventh and stands apart — at the foot of the panel rather than in this grid at all, because it is the one of them that is a physical thing attached to the bottom of the phone. Each of them **names what it is attached to** beside its glyph: the network, the paired device, what the cable is currently allowed to carry. Being lit says a radio is on, which is the half nobody has to be told; the name is the reading. It is set in the mono face, because it is a name that came from somewhere else rather than a word this interface chose, and it fades at the end rather than ellipsing, like every other reading here. Where there is no name to give — no cable, nothing paired — the state is said in words instead of the line being left blank, since an empty line under a lit glyph reads as a label that failed to load.

**An off face is the same symbol switched off, never a different one.** The bluetooth rune was redrawn as a broken-up version of itself and read as some other symbol entirely, which is the one thing an off face may not do: it is the rune with a line struck through it, the way the wifi and the microphone already were.

**Two levels stand against the right edge: brightness, then volume — and they are two bubbles rather than one module with two columns in it.** A slider that is being held has to be able to leave the panel on its own, which a column inside a shared box cannot do. They are the only readings in the panel that are neither a state nor something the phone decided — they are amounts a hand sets — so they are drawn as amounts: an upright column filled to its share, which is the same drawing the charge is, with the icon at the foot inside what it names. There is no knob, because the whole bar is the target.

They answer a **drag and never a tap**, exactly as the settings panel's sliders do and for the same reason doubled: a bar that jumps to wherever it was touched changes the phone because a finger came down on its way somewhere else, and on a panel that closes when its background is hit, that change is one nobody saw. The push that dismisses the panel is called off for a touch that started on a bar — a long upward drag setting the brightness was also a short upward flick, so the panel went away under the finger that was working it. A gesture that starts on a control belongs to that control.

Both ranges are the phone's own and are converted in Kotlin, so the page only ever deals in a share of a bar: the media stream's step count comes off the same line its level is read from, and full brightness is `config_screenBrightnessSettingMaximum` out of the framework's own resources — not 255, not a guess. A drag also switches auto-brightness off, since automatic put the value back a moment later and that reads as a slider that will not stay where it is put. Unlike a switch, nothing is read back after a drag: it is written per frame, and a round-trip returning the whole panel's state on each of those is a queue the thumb outruns.

**The cable is its own bubble at the foot of the panel now, not nested inside another one.** It used to stand inside the old foot module — a strip across the bottom of it, growing that module's height to carry it — and that stopped being true the moment the foot module became Main's own dock: a bubble inside Main would be two blur panes frosting the same pixels, exactly the trap the old nesting was written to avoid from the other direction. USB is a standalone `.quick-bubble` at the end of `#quick-panel`'s column instead, above the dock, wearing the same "unplugged is not drawn at all" rule it always did: an "off" cable is no cable, and a permanently greyed row saying so is height spent on the absence of a thing. Plugged in, pressing it is `svc usb setFunctions mtp`: the phone stops being a battery on the end of a wire and becomes a disk the other end can read and write. Pressed again it goes back to charging only, which is the state Samsung returns to on its own every time the cable comes out. The six states — do not disturb, extra dim, rotation, the battery saver, the screen recorder, the microphone — are circles, which is what is left of the switch once the track goes: the knob the icon was already riding in. A circle among squircles is deliberate here and not an accident of the split — a state is the one control in this panel with nothing in it but a glyph and no reading to lay out, so its shape can be the smallest one that holds the glyph, and every other shape on the screen is a squircle because a squircle is what a box of things looks like. Being lit is the whole reading, and lit is an inset shadow rather than a thicker border, because a border that thickens moves everything inside it by a pixel.

**A control wears the face of the end it is at**, where it has two (`GLYPHS_OFF`: wifi, bluetooth, mic). A slashed wifi says down at a glance; a dimmed one has to be compared against something before it says anything. A control absent from that map keeps its one glyph, which is right for a mode rather than a lack of one — and USB is there for want of an off shape, not by choice.

Pressing a round one **turns it a full circle and swaps the glyph at the half turn**, where the icon is upside down and least readable, so what the eye keeps is the face it ends on rather than a cut between two. A whole revolution is the one rotation that leaves nothing crooked behind. The turn belongs to the finger only: a correction arriving from `onTogglesChanged` a frame later, or the paint that runs when the panel opens, sets the same control without spinning a button nobody touched.

The charge is drawn as the battery itself: an upright cell with its terminal on top, standing at the top right and exactly as tall as the stack of links beside it. **The outline is not a border.** Three pixels of accent round a filled cell read as a slab in a frame, and the frame competed with the level inside it for what the eye was meant to look at; the cell is an unlit well — `rgba(10, 9, 13, 0.85)`, a 16px squircle, no border and no padding — with the charge poured straight into it, and the only edge in the whole drawing is the terminal on top. That terminal is what makes the shape read as a battery from the corner of an eye, and it is drawn as its own strip above the cell rather than as part of an outline: the cell clips everything in it so the level cannot climb out, and a nub inside that clip is a nub with its top cut off. There is no glyph beside the cell — that was the shape saying "battery" a second time next to a shape that already said it — and the only thing put over the level is the bolt, because being plugged in is not a level and cannot be shown by one. The number stands in the middle of the cell in white, because the level behind it is already the colour. **The level is flat and still**: solid `--charge-color` at full strength, standing at exactly the percentage. It had a moving surface once — two drifting crests and rising bubbles — and a level that is never still is a level being watched rather than read; taking them off is also what let the fill give up its group opacity and the seventeen pixels of headroom it was reserving for crests to break into. The colour comes from five **bands** — 100-86, 85-61, 60-36, 35-16, 15-0. Bands rather than a gradient, because what a glance wants off a battery is which of the five situations the phone is in, not the number said a second time.

**Plugged in outranks every band**, exactly as it does on the bar: the liquid goes the announcement's own green, so the bubble saying "charging" up there and the panel showing it down here are one colour rather than two greens, and it is written through `--charge-color` like every band rather than as an override laid over one. Nothing else marks it — the fizzing bubbles that used to rise through the liquid while a cable was in went with the crests they belonged to.

**Open, the Status bubble is not a bubble.** The panel it grows into is the battery and only the battery, so `isSkinned` drops its blob and its pane for as long as `open` is on: the glass that would stand behind the cell was a rounded slab of liquid the exact size of it, drawn a pixel behind a shape that is already its own outline. The skin comes back the moment `open` comes off, which is the frame the collapse starts, so the bubble is glass again for the whole of the journey home.

Reading them is a shell round-trip through Shizuku, and a bridge method runs on the WebView's own JavaScript thread — so it is **asked for rather than returned** (`requestToggles`, answered by `onTogglesChanged`). Returning the reading held the page still for the first frames of the very animation that asked for it. Each switch is drawn in the position the finger asked for and corrected when the shell answers: a switch that is a frame behind is better than a panel that waits for a shell before it opens, and a command the shell refused must not be left standing as a switch that says it worked.

The one switch with no shell behind it is the recorder: there is no setting for "is recording", so its state is read off the clock bubble — that is where a running recording already lives — and pressing it clicks One UI's own tile, because a tile is the only way in.

The main bubble's bare hold opens nothing at all now, and does not buzz either: it has no app to leave for and no longer has a panel to fall back on, and a haptic that promises something and then delivers nothing is worse than a gesture that is not there.

It has no arrival of its own past the first. It is born at the punch hole once, when the first connectivity payload lands, and it never leaves: what it stands for is true all the time.

### The battery announcement

**The only thing this bubble announces, and it announces all of it.** Everything else in it is read and drawn — what the phone is attached to is true all the time — but the charge changing is a *moment*, and it is this bubble's moment because this is the bubble already carrying the charge. All three of them are: being plugged in, falling past 30%, and falling past 10%. They used to be split between here and the Double at the bottom of the screen, which put the news and the reading it is news about at opposite ends of the phone for two of the three.

**One announcement in three moods.** The shape is the same drawing every time — the cell with a gap top and bottom and something passing through it — so that whatever it says is recognised as the battery before it is read: the bolt is being charged, a bar standing alone in an otherwise empty cell is what is left, and the bar with a dot under it is the same reading once there is too little of it to be a reading. The colour is the whole of the rest of the difference: green, amber, red. A level falling from low to critical under its own announcement recolours *and* re-glyphs where it stands rather than starting the run again — the two marks are twenty percent apart, so a fall past both inside one dwell is ordinary, and a red bubble still wearing the amber bar is the announcement contradicting itself.

It is a takeover, not a second shape: for a few seconds the bar stops reporting and says one thing. **What is there leaves before what is arriving comes**, which is [motion.md](motion.md)'s glyph-as-cause rule read at bubble scale — each reading is pulled inwards, one after another left to right so it reads as the row being cleared rather than as everything blinking off at once, and only when the bubble is empty does it open out around the glyph. The width is the consequence of the icon, as always. There is no percentage on it: the number was standing on the bar a second ago and what is news is which way it is going.

A reading leaves with a wobble, and **the wobble closes to nothing as it goes** rather than being something the reading survives: shaken at full size the row read as being knocked about instead of as being cleared, so the scale carries the departure and the shake is barely there under it.

Coming back is not the same motion backwards, because it is not the same event: what left was pushed aside and what arrives is landing. Each slot is thrown back in small and **turned a little off true, and swings straight past its mark** on the bubble family's own overshoot, at an angle randomised per slot so a row of them does not read as one rehearsed move. Underneath it the slots grow their own width back through the ordinary `arriving` state a wifi icon uses — the tilt rides on the inner element so the two compose rather than one owning the other. The popped slots are taken out of the DOM and the bubble is repainted for it: un-popping them in place would put the whole row back in one frame, which is the one thing this bubble never does. A second charge event while it is standing pushes the dwell out rather than playing the run again, the way an alert arriving on top of an alert does not announce itself twice, and an open panel outranks it in both directions: it will not start over one, and opening one puts it away.

### The slots

What the bubble is wearing is not a list in the order the code happened to push it. Each reading has a **slot number**, ascending left to right — USB 0, a transfer 1, the Modus 7, the link 8, the charge 9 — and what appears between two things already standing there is decided by its number. A new reading is given a number and needs nothing else changed.

None of them appear or disappear between two frames. A slot that is new is put in closed and let go on the next frame: it grows from nothing while rising into place, and the readings beside it are pushed along by its width rather than being repositioned. A slot that is gone closes and drops before it leaves the DOM. `grid-template-columns` from `0fr` to `1fr` is what gives an auto-width box a width to transition — nothing else does, and a fixed width per slot would be a second copy of every icon's size.

The bubble answers a **departure** with a bounce inwards: something left it, so for a moment it is smaller than the room it now needs. An arrival gets no such answer, because the arrival is already the whole of the motion — the icon is the cause and the width is the consequence, and a bounce on top of that is the bubble reacting to itself.

There is no crossed-out wifi and no greyed-out one. A link that is down is not something the phone is attached to, and an icon for it is the status bar reporting an absence: the slot holds the wifi glyph, or which generation the mobile link is (`4G`, `5G`, `E`), or — when the phone will not name the generation — the mobile bars, or it is not there. A link that is up is a thing the phone is attached to whether or not there is a word for it, and leaving the slot out for want of one made a mobile connection read as no connection at all. What made the slot empty for far longer was smaller and worse: `ACCESS_NETWORK_STATE` was never declared, so `registerDefaultNetworkCallback` threw and the `runCatching` around it turned a missing permission into a bubble that quietly never knew about wifi. Wifi's strength rides on the capabilities the default-network callback already carries, so its bars are real; the generation needs `READ_PHONE_STATE`, which is granted over adb by `grant.ps1` like everything else here rather than being asked for on the phone — One UI greys the toggle out for a sideloaded app anyway. A paired device's charge comes from the broadcast SystemUI's own meter reads (`android.bluetooth.device.action.BATTERY_LEVEL_CHANGED`), because asking `BluetoothDevice` for it is a hidden method and blocked — unheard, the level is simply unknown rather than wrong.

The paired charge stands in front of the phone's own, and the phone's own is always rightmost. A phone is charged by the person holding it; a pair of headphones runs out in the middle of something.

The phone's own charge goes **yellow below 31% and red below 16%**, and only that half of the slot: the paired device's charge sits in the same reading and is not the phone's alarm, so it is wrapped in its own element and the colour goes on the digits rather than on the slot. The two boundaries are the bottom two of the panel's five bands, so a charge crossing them changes in both places at once. The 31 is `BatteryWatch.LOW` plus one, so the colour changes on the same charge the announcement fires at; they were half a band apart, and a bubble that goes orange at 35 and only says so at 30 reads as the panel and the bar disagreeing about one phone. Three bands here against the panel's five, because the panel is being looked at and can afford a scale while the bar is being glanced past — and both are dulled well below the panel's, since this is standing over whatever is on screen and a saturated warning up there reads as an error rather than as a number getting small. Plugged in outranks the band: a phone at 9% on a cable is a phone being fixed.

A slot that is new is **let go after a forced reflow, not on the next animation frame**. A `requestAnimationFrame` callback runs before that frame's style recalc, so the class going on and coming off collapse into one computation and there is nothing to animate from — the slot appeared on the spot, which is what "the status bar is not animated when new entries pop in" was. Reading a layout property back is what makes the closed state get *computed*.

Everything in [bubbles.md](bubbles.md) still binds — born at the punch hole, liquid with whatever it comes near, drawn on the canvas, never a window of its own.

## Clock

**Built.** The time, over One UI's own clock at the far left of the bar, and the bubble the Now mods are shown in — see [What the Clock bubble carries](#what-the-clock-bubble-carries-the-now-mods). The time itself opens into nothing: there is no Extended state for it, because there is nothing the bubble could open out to say that the two digits are not already saying. A mod standing in it is what gives it a panel. It answers the hand like everything else here: it is pressed, it is pulled on the band, and **held it opens the clock app**, which is the same meaning the hold has on every other bubble — the clock *app*, not one screen inside it. `SHOW_ALARMS` is still how the app is found, since every phone has a clock and none of them agree on what it is called, but it is resolved to a package and that package's own launcher intent is what is started: fired raw it drops the user in Alarms every time, whatever they were last doing in there. The tap and the pull do their animation and land back where they started; that is the point of them, because a shape on this bar that does not move under a finger reads as painted on. It costs a proxy window for that, which it did not before, and it is the smallest one here.

It is the one thing up there that is true without anything having happened, and on its own it moves for exactly one thing: the minute turning over, which it answers with a short swell on the same curve everything else here lands on — the digits are the cause and the swell is the consequence, which is [motion.md](motion.md)'s rule and not an exception to it. Everything else it does is a mod's doing.

Its proxy is placed on exactly the box, whatever the box is at that moment — the digits, a mod's width, or the panel a mod opens into — and it is measured rather than told, so a mod that changes the size owes it a call and nothing else. It costs no window at all until the hold was added, and the rule that decided that has not changed: a proxy exists for what can be touched, and every pixel one covers is a pixel the shade swipe cannot start on. The height it reports is taken to the box's *bottom* rather than the box's own height, because the host hangs the window at the top of the screen — the last few pixels of an open panel could be seen and not touched otherwise.

The clock used to have to *leave* whenever the Now bubble came out, because the two wanted the same corner and no width was both legible and clear of it: it took `lit` off, went small, and came back when the light did, watched with a `MutationObserver` on the other bubble's class. All of that is gone with the bubble it was avoiding. There is one shape at that end of the bar now and it is never not there, which is also one less thing for the skin to mirror and one less departure to sequence.

It reads hours, minutes and seconds. The seconds stand to the right of the minutes, smaller and set on their baseline: they are the same reading at a finer grain rather than a third field, and five digits at one size read as a number instead of as a clock. They are tabular, so the sixty repaints a minute cost the bubble no width and the whole thing does not shift sideways as they run. The minute is still the only turn the bubble *moves* for — a swell every second is a bubble that never stops twitching — and it is the only turn that refits the proxy, since the seconds are two digits wide for the whole of it. The tick is scheduled to the next second boundary rather than every 1,000ms. A repeating interval drifts against the wall clock and eventually turns over late, which on a clock is the whole of what it had to get right.

## Lock screen

The lock-screen bubbles exist to replace what the lock screen already draws, not to stand next to it. All of them are planned.

### The steal

A mod on the lock screen is not copied down to the bottom and it is not drawn twice. It **belongs to a different bubble** for as long as the keyguard is up: the lock screen's Now bubble takes it, and the row at the cutout no longer has it at all. `LOCK_STEALS` names which mods are taken — media today — and the whole of the steal is one filter in `liveMods()`, because `liveMods()` is what the row's width, its satellites, its dots and its window are every one of them worked out from. Take the mod out there and all of them stop carrying it without being told; putting it back is the same filter going quiet.

So a new mod does not need lock-screen handling written for it. It needs a name in `LOCK_STEALS` and a face on the lock bubble, and the row lets go of it by itself.

Satellites follow the bubble that owns the mods, which on the lock screen is this one — planned, not built.

The stolen mod keeps its own identity down there rather than borrowing the row's. `--app-accent` is scoped to the lock bubble and written from the song it is carrying, because the row does not have that mod any more — nothing up there is keeping the colour right for a bubble that is no longer its.

Extended on this bubble is not a panel that appears over it: it is the same box at a greater height. It is hung off the bottom edge of the screen, so height is the only thing that changes and it grows upwards on its own, with the end the thumb is resting on never moving. A second element would have to be told all of that. It is entered by a tap or by a flick upwards, and left by either the same tap or a flick down — the direction of the flick is the direction the box moves.

Its transitions are named once in `--lock-transition` and every rule that adds a property to the list puts that list back rather than replacing it. The play drag's homing rule did replace it, and took the height with it: opening was instant, and the bug read as "Active is not animated" rather than as what it was — a rule about dragging quietly owning every other animation the bubble had. Same trap as the blanket `transition: none` in [motion.md](motion.md#motion-is-additive).

Closed, its layout is three bands rather than one row: the song at the top beside its cover, the transport spread across the whole width beneath it, and the timeline along the bottom. The width matters — this is the bubble worked with the thumb of the hand already holding the phone, and controls huddled at one end of a full-width box are the one place that thumb cannot reach.

Open, it is a record sleeve and takes about seventy per cent of the screen: the cover fills the width at the top, the song is read underneath it rather than beside it, and the transport grows into what is left. Nothing here is a second element — the cover is the same `<img>` at a different size, so it *travels* between the two layouts rather than being swapped for a bigger copy of itself. Its size is written as a length rather than a percentage for exactly that reason: width and height animate, and a height of auto with an aspect ratio does not.

The timeline is flush against the bottom edge with no padding under it, so the squircle cuts the ends of the line and it belongs to the shape. The dot marking the song's position rides the end of the filled part rather than being placed from the ratio a second time — one number, one owner, and it cannot disagree with the line it stands on.

A touch anywhere on a lock-screen bubble has to hold the screen on. These windows are not the keyguard's, so working the controls down there is watched by nobody and the screen goes off mid-gesture. `PowerManager.userActivity` is a signature permission and out of reach; `FLAG_KEEP_SCREEN_ON` set on the canvas at the touch and taken off again a while later is the same thing from the outside. It has to come off again — a flag left standing is a phone that never sleeps.

Unlocking is a **merge**, not a disappearance. It is one journey at two speeds, never two moves. It closes to `LOCK_PINCH_SCALE` on an ease that leaves slowly and ends fast and past its mark, and it is travelling the whole time it does — at `LOCK_CRAWL`, a quarter of full speed — then opens up to full speed for the rest of the way once there is nothing left to close. Held still while it closes it reads as two unrelated things in turn, a resize and then a slide. Size and travel are two animations on two properties rather than one keyframe list, because a keyframe's easing owns every property in it and these two want opposite ones. It travels on one goo layer with the bubble, closing over the journey to the bubble's own measured size — a shape wider than what is taking it in has not arrived yet. The `catchInto` is there for the swell only; the merge itself ends the frame the drop's centre reaches the bubble's, watched per frame rather than timed, because the flight is eased and its distance depends on where the bubble is standing, so that instant is not a number that can be written down beforehand. At it the drop goes out on the spot, the row takes its mod back in the same frame, and the bubble is knocked `LOCK_BUMP` up and back down — added to its transform, never set, since transform belongs to whatever is dragging it.

The steal outlives the keyguard by exactly one flight. `stealHeld` keeps `liveMods()` filtering the mod out while the drop is in the air, and the catch's `entered` step is what lets it go — so the row opens out *because* the drop arrived. Released when the keyguard went instead, the bubble at the cutout had already grown and settled before the thing it grew for had set off, and the two read as unrelated events happening near each other.

The flag saying it is flying is set *before* the row is repainted, never after. Taking the mod back is what repaints the row, and repainting the row repaints this bubble — which asks `lockMod()` again, is told the keyguard has gone, and takes `showing` off the very thing that is about to fly. It keeps `showing` for the whole journey: that class is what the skin reads to decide the shape is one of the row's at all, and taken off at the start it would spend the flight outside the liquid and arrive as a separate object fading on top of the bubble — the exact bug the torch drop had.

- **Lock** stands where the lock icon is. **Built.** Unlocking springs it open and sends it in one move: the shackle lifts and tilts, the shape pops past its own size, and it is travelling into the Main bubble while it does. The pop is the cause and the journey is the consequence, so they overlap rather than queueing — held still until the shackle had finished, the opening and the flight read as two unrelated things happening in turn. It arrives exactly as the Lock Now bubble does: `catchInto` for the swell, the merge ended the frame the drop's centre reaches the bubble's rather than on an overlap share, and the bubble knocked `LOCK_BUMP` up and back down by what has just gone into it. Where it stands (`PADLOCK_BOTTOM`) is a measurement off the phone, raised now that the notification bubbles stand below it rather than merely near it, and `padlockOffsetDp` is the settings panel's own fine adjustment on top of that default — a Y offset rather than the X every other lock-screen offset is, since this bubble's problem is standing clear of what has grown up underneath it, not sliding sideways.
- **Rubber-banding the unlock swipe is not built and cannot be**, at least not from here: nothing exposes the keyguard's own swipe progress to an unprivileged app. There is no callback, no window insets animation for it, and reading it off touches we do not receive is not reading it. It stays out of the plan as a wish rather than a task until something on the device turns out to publish it.
- **Notification and Bottom Now share one container**, `#lock-stack`, rather than being placed against the screen independently — a flex column roughly 60% of the screen tall, anchored to the bottom the way Now always was. Now is the last child, so flex-end packing keeps it glued to the bottom edge whatever height it is; the notes are the sibling before it, with a 3% gap of clear separation and the room to shrink as Now grows. That single layout rule is the whole of the quirk asked for: **Now opening pushes the notes up and, once there is no room left, out of view** — nothing measures either box by hand, flex does both moves as one relayout.

  **Notification** bubbles overlap the system's own lock-screen notifications and take their place. **Built.** One bubble per *conversation* — newest at the bottom, nearest the thumb and nearest Now, scrolling up into the past the way a chat thread does — with the rest counted rather than listed once past `NOTES_LIMIT`, the way the row counts its hidden mods. Redrawn whole rather than reconciled: a lock screen is looked at and not worked, so a diff of five rows costs more to get wrong than to redo.

  Each one wears the notification's own icon on its left — the large icon the platform gave the notification, which for a messaging app *is* the sender's avatar, exactly the picture its native notification wears, falling back to the app's own small icon and then to a plain initial when neither is offered. A ring in the app's accent colour stands in for what used to be a separate coloured dot.

  **Tapped, a conversation opens in place**: every earlier line it is holding grows in beneath the newest one and the notes above it are pushed along, on `grid-template-rows` from `0fr` to `1fr` — the same native from-nothing-to-content transition the Status bubble's slots already use, so every neighbour reflows on the same frames rather than snapping to a size this one decided alone. Only one is open at a time. **Held, it opens the app** the way a hold means on every bubble here. **Swiped sideways it dismisses**, dragging its neighbours along and closing the gap behind it exactly as a row in the notification tab does — the two share the gesture code (`swipeDismiss.js`) because it is one mechanic wearing two lists. What it does not have is the object drag every other bubble gets: no rubber band, no `dragRadius`, because nothing here is meant to be picked up and carried.

  Its container is `overflow: visible` and the scroller *inside* it is what clips, which is the no-clipping rule doing its job rather than an exception to it — these are bubbles and a bubble's overshoot may not be cut off.

  It is the largest touch proxy in the project and the one place that is affordable: it stands on the lock screen well below the strip the shade swipe starts on, and it is given no size at all while the phone is unlocked. Affordable is not unbounded, though, and the box it is measured from may never claim room it is not using — sized to fill the stack rather than to its own content (`flex: 1` instead of `flex: 0 1`), one notification's proxy covered most of the lower screen and swallowed the keyguard's own swipe-up-to-unlock.

  Both of these bubbles are a setting: `notesShown` and `padlockShown` take the whole bubble away rather than hiding a detail of it — nothing drawn, nothing skinned, no proxy — so the lock screen is left exactly as One UI drew it.

  **Bottom Now** replaces the Now Bar. A song playing shows as a wide bubble at the bottom carrying that mod's own controls — back, play/pause, next. Tap expands the controls; Haptic opens the app. It is the only lock-screen bubble with states of its own.
